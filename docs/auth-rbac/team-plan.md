# 本周认证与 RBAC 六人分工

## 一、人员分工

| 负责人 | 负责内容 | 交付物 |
|---|---|---|
| **段欣懿** | 公共契约、数据库与文档收口、代码合并、最终验收 | OpenAPI、接口汇总、增量 SQL、初始化数据、权限编码清单、集成分支和验收记录 |
| **同学 1：认证核心后端** | Spring Security、JWT＋Redis 会话、统一登录入口、用户名密码登录、退出和续期 | Security 配置、登录接口、JWT 校验、Redis 会话、Logout 和 Refresh |
| **同学 2：验证码与邮件后端** | 图片验证码、邮件 OTP、Mailpit、注册、邮箱 OTP 校验和找回密码 | 验证码接口、邮件 OTP、注册接口、找回密码接口及测试 |
| **同学 3：RBAC 与越权后端** | 用户分配角色、角色管理、角色授权、权限资源树、接口权限和文件归属检查 | 6 个 RBAC 接口、`@PreAuthorize`、垂直和水平越权测试 |
| **同学 4：认证前端与公共骨架** | 登录、注册、找回密码页面，以及 Axios、Token、Refresh、CSRF 和路由守卫 | 认证页面、Auth Store、请求拦截器、401 处理和路由守卫 |
| **同学 5：权限管理前端** | 用户管理、角色管理、权限资源树、角色授权、动态菜单和 403 页面 | 管理页面、角色权限勾选、菜单展示和无权限页面 |

## 二、公共内容由段欣懿统一收口

以下内容其他人不能私自修改，需要先提交变更说明，由段欣懿确认：

- `openapi-v1.json` 和接口汇总；
- 数据库设计、增量 SQL 和初始化数据；
- `pom.xml`；
- `application.yml`、`application-dev.yml`；
- 统一响应结构；
- 数字业务错误码；
- 全局异常处理；
- 权限编码清单。

新增依赖、字段、错误码或权限编码时，先说明原因，不要让自己的 AI 直接修改公共文件。

## 三、三个关键边界

### 1. 登录入口只由同学 1 汇总

- `/api/v1/auth/login` 的 Controller 只由同学 1 维护；
- 同学 2 不新增另一套登录接口；
- 同学 2 提供邮箱 OTP 校验能力，由同学 1 接入统一登录流程。

### 2. 会话撤销能力只由同学 1 提供

同学 1 统一提供“撤销用户全部会话”的公共能力：

- 同学 2 在重置密码后调用；
- 同学 3 在修改用户角色、角色权限或数据范围后调用；
- 同学 2、3 不各自实现一套 Redis 撤销逻辑。

### 3. 前端公共骨架只由同学 4 维护

同学 4 统一负责：

- Axios 请求和响应拦截；
- Access Token 内存管理；
- Refresh 自动续期；
- CSRF Token；
- 401 处理；
- 路由守卫；
- Auth Pinia Store。

同学 5 使用这些公共能力，不重新生成一套 Axios、Auth Store 或路由守卫。

## 四、冻结的公共约定

开始业务开发前，已经确定：

- 12 个新增接口的方法、路径、请求和响应；
- `challengeId`、`captchaId` 等字段；
- Access Token 和 Refresh Cookie 的使用方式；
- 统一响应结构和数字错误码；
- 初始权限编码；
- 数据库增量字段和索引；
- 三个演示账号：

| 账号 | 角色 | 用途 |
|---|---|---|
| `admin_demo` | `ADMIN` | 用户、角色和权限管理 |
| `student_a` | `STUDENT` | 文件上传和本人数据测试 |
| `student_b` | `STUDENT` | 水平越权 IDOR 测试 |

前端先根据冻结的 OpenAPI 做 Mock 页面，不必等后端全部完成。

## 五、分支与合并顺序

集成分支：

```text
feature/rbac-auth
```

五个人分别使用：

```text
feature/auth-core
feature/auth-verification
feature/rbac-backend
feature/auth-frontend
feature/admin-frontend
```

所有分支先合并到 `feature/rbac-auth`，不要直接修改 `develop`。

合并顺序：

1. 段欣懿提交公共契约、增量 SQL 和初始化数据；
2. 合并同学 1 的认证主干；
3. 合并同学 2 的验证码、注册和找回密码；
4. 合并同学 3 的 RBAC 和越权防护；
5. 合并同学 4 的认证前端和公共骨架；
6. 合并同学 5 的权限管理页面；
7. 段欣懿组织端到端测试和最终验收。

## 六、阶段性检查点

### 检查点一：认证主干

- `admin_demo` 能通过用户名密码登录；
- Access JWT 能被 Spring Security 校验；
- Redis 会话能够查询；
- 退出后旧令牌不能使用；
- Refresh 能换取新令牌。

### 检查点二：验证和注册

- 图片验证码不能重放；
- Mailpit 能收到 OTP；
- 注册后默认分配 `STUDENT`；
- 找回密码要求 `challengeId`、邮箱和场景完全匹配；
- 重置密码后旧会话失效。

### 检查点三：RBAC 与越权

- 修改用户角色后旧会话失效；
- 修改角色权限后相关用户旧会话失效；
- `@PreAuthorize` 能拦截垂直越权；
- 文件下载检查当前用户和 `uploader_id`；
- 学生 A 不能下载学生 B 的文件；
- 前端菜单和权限树与后端结果一致。

### 检查点四：端到端验收

- 两种登录方式都能使用；
- 注册和找回密码可完整演示；
- 角色和权限管理可完整演示；
- 退出、续期和会话失效可完整演示；
- 所有接口响应使用数字业务码；
- OpenAPI、接口汇总、SQL、Apifox 和测试记录一致。

## 七、提交要求

每人提交时必须提供：

- 分支名和提交记录；
- 修改文件清单；
- 实际运行结果；
- 测试截图或接口响应；
- 使用的公共接口和权限编码；
- 未解决的问题及需要协调的地方。

只有 AI 生成的代码、没有实际运行，不算完成。

至少提前一天完成合并，并验证两种登录、注册、找回密码、角色授权、退出、会话失效、垂直越权和水平越权。
