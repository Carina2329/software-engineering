## 一、本次完成的小闭环

平台管理员可以维护组织和学校；学生、教师可以查询并选择学校；学校管理员可以确认本校用户；带范围的管理员角色可以在后端真正限制数据和写操作。

必须形成：

```text
平台超级管理员创建学校/主办组织
  → 授予组织管理员范围角色
  → 学生选择学校
  → 学校管理员确认归属
  → 其他学校管理员无法访问该学校数据
```

## 三、范围

### 组织主档

- 学校 `SCHOOL`
- 省级主办方 `PROVINCE_ORGANIZER`
- 国家级主办方 `NATIONAL_ORGANIZER`
- 平台组织 `PLATFORM`
- 组织编码、名称、类型、省份、状态和版本
- 平台管理员创建、查询、修改组织
- 组织停用不物理删除历史数据

### 范围角色

- `GLOBAL`
- `ORGANIZATION`
- `PROVINCE`
- `EVENT`
- 平台超级管理员指定组织首个管理员
- 组织管理员在授权范围内指定赛事负责人
- 角色、范围和有效期变更写审计并撤销旧会话
- 不接受客户端通过传任意组织 ID 扩大权限

### 学校选择和确认

- 登录用户查询学校列表
- 学生和教师首次选择学校
- 学校归属 `PENDING / VERIFIED / REJECTED` 状态
- 学校管理员通过现有用户管理页处理待审核队列
- 确认、驳回原因、审核人和审核时间
- 已确认学校不能由本人直接切换

## 五、验收场景

1. 平台管理员创建四川省的 A 学校、B 学校和省级主办方。
2. A 学校管理员只能管理 A 学校用户，无法访问 B 学校。
3. 四川管理员只能管理四川省范围。
4. 学生只能从已启用学校中选择。
5. 学校管理员在现有用户管理页确认后，学生学校归属变为 `VERIFIED`。
6. 驳回必须填写原因，学生可修改后重新提交。
7. 已确认学校不能被学生直接修改。
8. 角色范围变更产生审计并撤销用户旧会话。
9. 不同组织管理员的越权请求返回 403 或 404，不泄露其他组织数据。
