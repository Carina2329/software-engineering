## 1. 引言

### 1.1 编写目的

本文档用于定义"AI 大学生学科竞赛全流程智能服务平台"的系统边界、用户角色、功能需求和非功能需求，作为后续数据库设计、接口设计、系统详细设计与开发测试的依据。

### 1.2 系统目标

建设一个覆盖高校学科竞赛完整生命周期的平台，并支撑赛事一届一届持续办下去：

- **跑通一届赛事的完整链路**：管理员发布竞赛、学生报名组队选题、提交作品、AI 辅助预审、专家盲评、成绩公示；
- **用 AI 解决竞赛场景的真实痛点**：作品对照评审细则做提交前预审、基于作品内容的答辩预演、作品原创性初检、竞赛政策智能问答；
- **让数据沉淀下来产生长期价值**：获奖作品入展厅、学生生成竞赛履历、多届数据形成趋势看板。

### 1.3 术语定义

| 术语 | 含义 |
| --- | --- |
| 竞赛 | 一类赛事，例如"软件杯"，可举办多届 |
| 届次 | 竞赛的一次具体举办实例，例如"2026 年软件杯校内选拔赛" |
| 赛题 | 届次下设的题目/方向，队伍选题后参赛 |
| 队伍 | 由若干学生组成的参赛单位，含队长、队员和指导教师 |
| 申报书/作品 | 队伍提交的文档、代码包、演示材料等 |
| AI 预审 | 对照本届评审细则，对上传作品做提交前质量检查 |
| 原创性初检 | 作品与本届及往届已提交作品的相似度比对 |
| 答辩预演 | AI 扮演评委，基于作品内容进行追问式模拟答辩 |
| 盲评 | 评审专家看不到参赛队身份信息的评审方式 |
| 异议申诉 | 成绩公示期内队伍对成绩提出异议、管理员复核的流程 |

## 2. 总体描述

### 2.1 用户角色

| 角色 | 主要职责 |
| --- | --- |
| 学生 | 注册登录、完善档案、组建或加入队伍、选题、提交作品、查看预审报告、答辩预演、查看成绩与竞赛履历 |
| 指导教师 | 确认指导关系、查看名下队伍进度与预警、指导学生修改作品、查看队伍预演记录 |
| 评审专家 | 接收评审任务、在线查看作品、按评分维度打分、填写评语 |
| 竞赛管理员 | 发布竞赛与届次、配置赛程/赛题/评审规则、分配评委、处理异议、公示结果、维护知识库、查看全部数据 |

### 2.2 业务主流程

本文档第三章的功能需求按此流程组织，每个模块均标注所属阶段。

```text
【赛前】
管理员创建竞赛届次并发布赛程规则
        ↓
学生注册/完善档案 → 创建队伍或加入队伍 → 选择指导教师 → 报名审核
        ↓
选择赛题（可查看 AI 适配度分析与能力缺口提示）

【赛中】
        ↓
提交申报书/作品材料（版本化管理，可多次修改）
        ↓
AI 作品预审（对照评审细则）→ 按问题清单修改 → 截止后锁定作品
        ↓
（全程）进度风险预警：临期未提交 / 长期无进展 / 预审多次未通过

【评审】
        ↓
管理员分配评审专家（盲评）→ 原创性初检结果供评委参考
        ↓
专家按评分维度打分 → 系统按权重汇总
        ↓
成绩公示 → 公示期内可异议申诉 → 管理员复核 → 获奖名单确认
        ↓
（评审前任意时刻）队伍可进行 AI 答辩预演

【沉淀】
        ↓
届次归档 → 获奖作品进入展厅 → 学生生成竞赛履历 → 多届数据看板与导出
```

### 2.3 多届赛事与数据组织

平台按"竞赛 → 届次"两级组织数据：

- **竞赛**是稳定的主档（名称、级别、主办方、简介），**届次**是一次具体举办（赛程节点、赛题、队伍、作品、评审均挂在届次下）；
- 同一竞赛可创建新届次，历史届次数据只读归档，不可修改；
- 届次归档后产生三类沉淀数据：获奖作品（进展厅）、参赛与获奖记录（进个人履历）、过程统计数据（进多届趋势看板）；
- 原创性初检的对照范围 = 本届已提交作品 + 历史届次归档作品。

## 3. 功能需求

### 【全程支撑】

### FR-01 用户与权限管理（P0）

#### 功能描述

1. 支持学生、指导教师、评审专家、竞赛管理员四类角色注册与登录；
2. 采用 RBAC 权限模型，菜单权限和数据权限相互隔离；
3. 学生维护个人档案：学号、学院、专业、年级、技能标签、兴趣方向、参赛经历；
4. 指导教师维护个人档案：职称、学院、研究方向、可指导队伍数；
5. 管理员可启停用户、重置密码、调整角色。

#### 关键业务规则

- 一个用户可以同时具备"指导教师"和"评审专家"角色，但同一届次中不能评审自己指导的队伍；
- 学生只能查看自己所在队伍的数据，教师只能查看名下队伍，管理员可查看全部。

### FR-02 规则知识库问答（P0）

#### 功能描述

1. 管理员维护竞赛政策与规则知识库，内容类别覆盖：学校竞赛管理办法、A/B 类竞赛目录、学分认定规则、报销流程、时间节点、作品格式要求等，条目随资料持续更新；
2. 支持上传规则文档后自动拆分入库，管理员可编辑和下线条目；
3. 学生和教师通过自然语言提问，AI 基于知识库多轮回答并引用来源（文档名/条目编号/条款）。

#### 关键业务规则

- 回答必须引用知识库来源，未命中的问题明确提示"该问题不在知识库中"，不允许凭空编造；
- 知识库建设不设条目数量硬指标，以覆盖上述类别、常见咨询可命中为验收依据。

### FR-03 消息提醒与风险预警（P1）

#### 功能描述

1. 站内消息覆盖：报名审核结果、选题审核结果、作品截止提醒、评审任务提醒、成绩公示通知；
2. 风险预警列表（管理端与指导教师端），满足以下规则的队伍自动标红：

- 距报名或作品截止不足 X 天（X 由管理员按届次配置）仍未完成对应动作；
- 队伍连续 N 周（默认 2 周）无任何提交或修改动作；
- 作品连续多次（默认 3 次）未通过 AI 预审；

3. 支持消息已读/未读状态。

#### 关键业务规则

- 预警仅作提醒，不产生任何强制性状态变更；
- 指导教师只看到名下队伍的预警，管理员看到全部。

### 【赛前】

### FR-04 竞赛与赛程管理（P0）

#### 功能描述

1. 管理员创建竞赛主档：名称、级别（校级/省级/国家级）、主办方、简介；
2. 在竞赛下创建届次并配置赛程：报名截止时间、作品截止时间、评审时间、公示时间等里程碑节点；
3. 支持届次状态流转：草稿 → 报名中 → 作品提交中 → 评审中 → 公示中 → 已归档；
4. 发布竞赛通知和规则附件，支持置顶与修改。

#### 关键业务规则

- 报名截止后不可再创建队伍或加入队伍；
- 作品截止后队伍不可再修改提交内容；
- 已归档届次的所有数据只读。

### FR-05 报名与组队管理（P0）

#### 功能描述

1. 队长创建队伍并设置队伍名称，可邀请队员加入，队员也可通过队伍编号申请加入；
2. 队长选择指导教师并提交报名；
3. 报名审核为两级：指导教师确认指导关系 → 管理员终审（通过/驳回，驳回须填写理由）；
4. 支持队员退出、队长转让、队伍解散。

#### 关键业务规则

- 每支队伍人数按届次配置限制，默认 1–5 人；
- 同一学生同一届次只能属于一支队伍；
- 队伍未通过报名终审前不可提交作品；
- 报名被驳回后可修改信息重新提交，截止前不限次数。

### FR-06 赛题与智能选题（P1，基础选题功能为 P0）

#### 功能描述

1. 管理员按届次导入赛题：名称、方向、简介、技术需求、难度、可报名队伍数；
2. 队伍从赛题列表中选择题目，已满员的赛题不可再选（P0）；
3. AI 适配度分析：对照队员技能标签与赛题技术需求，输出各赛题的适配度分析和**能力缺口提示**（如"该题需要 XX 技术，队内暂无成员掌握"），辅助队伍决策（P1）；
4. 支持管理员审核队伍选题，防止重复与冲突。

#### 关键业务规则

- 一个队伍在同一届次只能选择一个赛题；
- 选题后允许在报名截止前更换一次，由管理员审核。

### 【赛中】

### FR-07 作品提交与版本管理（P0）

#### 功能描述

1. 支持上传申报书（Word/PDF）、代码压缩包、演示视频链接、Git 仓库地址；
2. 作品以"提交版本"方式管理，每次修改生成新版本，保留版本历史；
3. 作品截止前队伍可撤回并重新提交；截止后自动锁定，禁止修改。

#### 关键业务规则

- 文件类型、大小按届次配置校验；
- 只有报名终审通过且已选题的队伍才能提交作品。

### FR-08 AI 作品预审与原创性初检（P0，原创性初检为 P1）

#### 功能描述

1. **AI 预审（P0）**：AI 解析申报书/论文 PDF/Word 文档，提取标题、研究内容、技术方案、进度安排等关键信息；
2. 预审依据为该届次管理员配置的**评审维度和作品规范**（与 FR-09 评分配置联动），逐项检查并输出预审报告：总体评价、问题清单、严重程度、修改建议（如"对照'功能完整度'维度，缺少 XX 材料，预计影响该维度得分"）；
3. 队伍依据报告修改后重新上传，系统重新预审，报告保留历史记录；
4. **原创性初检（P1）**：作品提交后与本届已提交作品及历史届次归档作品做文本相似度比对，输出相似度提示；可选给出 AIGC 内容占比提示。

#### 关键业务规则

- 预审报告仅对队伍和指导教师可见，不直接作为评审分数；
- 原创性初检结果仅对管理员和评审专家可见，作为评审参考，不自动产生处罚；
- 预审由异步任务执行；AI 服务异常时不阻塞作品提交与评审主线（见 NFR-03）。

### 【评审】

### FR-09 评审管理（P0）

#### 功能描述

1. 管理员配置评分维度及权重，例如：创新性 20%、功能完整度 30%、技术难度 20%、文档规范 15%、现场/视频表现 15%（该配置同时作为 FR-08 预审依据）；
2. 管理员把参赛作品分配给多个评审专家，支持盲评模式（评委看不到队伍名称、成员、指导教师）；
3. 评审专家在线查看作品、按维度打分并填写评语；
4. 系统按权重汇总总分并生成排名。

#### 关键业务规则

- 评审专家不能评审自己指导的队伍；
- 一份作品至少分配两名专家，取平均或按规则汇总；若两名专家分差超过阈值（如 20 分），管理员可加派第三名专家；
- 所有专家提交后，管理员才可进入成绩公示。

### FR-10 答辩预演（P1）

#### 功能描述

1. 队伍选择预演场景："开题/中期/最终答辩"；
2. AI 扮演**看过本队作品的评委**，基于作品内容生成追问，覆盖选题意义、技术方案细节、创新点与已有方案的区别、工作量真实性等评委常见攻击角度；
3. 学生文字或语音作答，AI 从**内容扣题度、技术应答准确度、临场表达**三个维度评价并给出建议；
4. 输出答辩预演报告，含"可能被评委攻击的薄弱点清单"，保存历史记录。

#### 关键业务规则

- 预演基于本队已提交的作品内容生成问题，不使用通用题库；
- 预演结果不进入正式评审成绩，可作为训练记录由指导教师查看。

### FR-11 成绩公示与异议处理（P1）

#### 功能描述

1. 管理员确认排名后发布成绩公示，公示时长按届次配置；
2. 公示期内队伍可对成绩提出异议，填写异议理由；
3. 管理员复核异议：维持原成绩或调整，处理结果通知队伍；
4. 公示期结束且无未处理异议后，生成获奖名单并确认发布。

#### 关键业务规则

- 每支队伍对同一届次最多提出一次异议；
- 异议处理全程留痕（提出时间、处理人、处理结果）。

### 【沉淀】

### FR-12 成果沉淀与展示（P1）

#### 功能描述

1. **获奖作品展厅**：届次归档后，获奖作品经管理员审核进入展厅，按竞赛级别、年份、赛题分类展示（作品文档、演示材料、队伍成员与指导教师信息），供后续参赛学生参考；
2. **个人竞赛名片**：系统根据学生参赛与获奖数据自动生成竞赛履历（参赛次数、获奖等级、技能标签、承担角色），可导出 PDF，用于求职简历。

#### 关键业务规则

- 展厅只展示获奖且审核通过的作品，未获奖作品不对外展示；
- 学生可设置自己的获奖记录是否在展厅中展示姓名。

### FR-13 数据看板与导出（P1）

#### 功能描述

1. 看板包含三个核心图表：

- 各学院参赛人数与获奖分布；
- 各竞赛/赛题报名热度与作品通过率；
- 历年（多届）竞赛成绩趋势；

2. 支持按学院、专业、届次筛选；
3. 支持导出 Excel/PDF 报表与成绩单。

## 4. 非功能需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| NFR-01 | 权限安全 | 登录密码加密存储；JWT 鉴权；越权访问必须被拦截 |
| NFR-02 | 数据隐私 | 演示与测试只使用模拟数据，禁止出现真实学生个人信息 |
| NFR-03 | 可用性 | AI 服务（预审、问答、预演）异常或超时时不阻塞作品提交、评审、成绩发布等主业务流程，页面给出明确降级提示 |
| NFR-04 | 性能 | 常规列表接口在模拟数据量下响应流畅；AI 预审异步处理不阻塞页面 |
| NFR-05 | 兼容性 | 支持 Chrome/Edge 等主流浏览器，PC 端优先 |
| NFR-06 | 可部署 | 支持 Docker Compose 一键部署，数据库脚本可从零初始化 |
| NFR-07 | 可维护 | 前后端工程规范与命名规范统一，代码经过评审与格式化 |
| NFR-08 | 可追溯 | 作品版本、评审过程、异议处理、知识库条目保留历史记录 |

## 5. 数据方案

| 数据类型 | 数据来源 | 说明 |
| --- | --- | --- |
| 竞赛/赛题/规则 | 官方竞赛资料、学校通知 | 公开信息，标注来源 |
| 政策知识库 | 学校竞赛管理办法等公开资料整理 | 覆盖 FR-02 所列类别，每条含来源标注 |
| 队伍与作品 | 本小组自己的课程设计项目 | 作为第一支真实参赛队伍演示 |
| 其他队伍 | 种子脚本生成 | 模拟 8–10 支队伍、多种进度状态（含触发预警的状态） |
| 历届数据 | 种子脚本生成 | 模拟 2–3 个历史届次，支撑展厅、趋势看板与原创性初检 |
| 评审打分 | 脚本按分布生成 + 组内真实预演 | 用于看板和结果公示演示 |
| AI 测试集 | 人工构造 20 份带已知问题的申报书 | 用于验证 AI 预审效果并量化指标 |

## 6. 验收标准

### 6.1 必达项（对应 P0，主线走通即达成）

1. 管理员创建竞赛届次、配置赛程并发布；
2. 学生完成组队、选导师、通过两级报名审核、选择赛题；
3. 上传一份真实文档触发 AI 预审，生成对照评审细则的问题清单，修改后重新预审；
4. 评审专家完成盲评打分，系统按权重汇总，管理员发布成绩；
5. 规则问答能命中知识库并引用来源，超库问题明确拒答；
6. 四类角色登录后数据互不可见越权；
7. 人为断开 AI 服务后，作品提交与评审流程仍可走通（验证 NFR-03）。

### 6.2 加分项（对应 P1，按实际完成情况展示）

1. 风险预警列表正确标红三类异常队伍；
2. 完成一次答辩预演并生成含薄弱点清单的报告；
3. 获奖作品进入展厅，学生导出个人竞赛履历 PDF；
4. 看板展示三个核心图表并可导出报表；
5. 完成一次异议申诉与复核的全流程；
6. 原创性初检输出相似度提示。
