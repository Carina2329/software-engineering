### v1.2.0 重要变化

- 每届只能选择 `PRESET_UNLIMITED`、`PRESET_LIMITED`、`SELF_PROPOSED`、`NO_TOPIC` 之一，不支持混合模式。
- `contest_topic.max_teams` 可为空，空值表示不限队伍数量。
- 限额赛题默认 `REVIEW`，`FIRST_COME` 仅在明确启用的届次使用。
- 自拟项目默认需要管理员审核，必填项目名称、方向和简介。
- 同一队伍同时只能有一个有效指导教师申请；教师接受时校验并占用指导名额。
- 队伍默认最多更换一次赛题或项目。
- 新增 EP-079 赛题/项目审核、EP-080 教师申请撤回、EP-081 至 EP-084 队伍邀请接口。

### v1.2.1 重要变化

- 邮件 OTP 异步发送使用 RabbitMQ，HTTP 202 只表示任务已入队。
- RabbitMQ 不可用只阻止新发送任务，不影响用户名密码登录或已有 OTP 的 Redis 校验。
- Redis Lua 原子完成登录、验证码和 OTP 限流计数与 TTL 设置。
- 重发 OTP 使旧 challenge 失效；失败回滚使用原子比较，不能误删新请求。
- Nginx 429 使用统一结构，真实展开 `$request_id`，并与 `X-Trace-Id` 一致。
- RabbitMQ 采用至少一次投递，不承诺所有崩溃窗口的 exactly-once。
- 不新增接口、数据库表、业务错误码或网关。

## 公共错误码变更

- `50003`：认证链路依赖暂不可用，包括 Redis、幂等或认证邮件队列；HTTP 503；可重试。
- `50001` 仍专指 AI 服务暂不可用。
- `50002` 仍专指对象存储暂不可用。
- `20001`、`40002` 及其他既有错误码的含义保持不变。
